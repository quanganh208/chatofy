# Code Standards

Only rules something enforces are listed here, each with the file that enforces it. A
rule that lives only in prose drifts; if you add one, add the check with it.

## Toolchain

- **Node 24** (`.nvmrc`; CI pins the same), **pnpm 11** via Corepack (`packageManager`
  in the root `package.json`), Turborepo for every cross-workspace task (`turbo.json`).
- Workspaces: `apps/*` and `packages/*` (`pnpm-workspace.yaml`). The Python sidecars in
  `services/` and the harnesses in `benchmarks/` are standalone `uv` projects, outside
  the pnpm graph.
- Dependency pins and security floors live in `pnpm-workspace.yaml` overrides, each with
  the reason it exists. Add the reason when you add a floor.

## Formatting

Prettier, configured in `.prettierrc.cjs`: semicolons, single quotes, trailing commas,
print width 100, two-space indent. `.editorconfig` sets UTF-8, LF, final newline.

`lint-staged` (`.lintstagedrc.json`) runs `prettier --write` on staged
`ts/tsx/js/mjs/cjs/json/md/yml/yaml` from the husky `pre-commit` hook, so formatting is
not a review topic.

## TypeScript

`tsconfig.base.json`, extended through the presets in `packages/config/tsconfig/`
(`base`, `library`, `nestjs`, `nextjs`, `react-native`):

- `strict`, plus `noUncheckedIndexedAccess` — an indexed read is `T | undefined`.
- `verbatimModuleSyntax` with `NodeNext` resolution — type-only imports must say so.
- `pnpm typecheck` runs `tsc --noEmit` (or `tsc -b --noEmit`) in every workspace.

## Linting

Flat ESLint presets in `packages/config/eslint/`: `base.cjs`, extended by `nestjs.cjs`,
`nextjs.cjs` and `react-native.cjs`.

| Rule                                         | Level | Note                                    |
| -------------------------------------------- | ----- | --------------------------------------- |
| `@typescript-eslint/consistent-type-imports` | error | inline `type` imports                   |
| `unused-imports/no-unused-imports`           | error | auto-fixed by `--fix`                   |
| `unused-imports/no-unused-vars`              | warn  | prefix with `_` to mark intentional     |
| `@typescript-eslint/no-explicit-any`         | warn  |                                         |
| `no-console`                                 | warn  | `off` in the NestJS preset (server log) |

Mobile lints through `expo lint`. `pnpm knip` (`knip.json`) reports unused files,
exports and dependencies; its per-workspace entries explain the non-obvious ones (WXT
entrypoints, for instance, are loaded by the browser and imported by nothing).

## Contracts between apps

Every request and response shape is a zod schema in `packages/types`, and the
TypeScript type is inferred from it — never written by hand beside it. The recipe, the
response envelope and the enforcement points are in
[Contracts, Envelope and Languages](./architecture/contracts-and-languages.md).

Languages are entries in one registry, `packages/types/src/domain/languages.ts`; code
derives directions from it rather than naming `vi` or `en`.

## Structure and naming

- **API**: one NestJS module per domain under `apps/api/src/modules/<domain>/`
  (`auth`, `conversations`, `translate`, `minutes`, `storage`, …), each with its
  `*.module.ts` and, where it takes input over HTTP, a `dto/`. Module layout: [Modules, Browser Extension and CI/CD](./architecture/modules-extension-ci.md).
- **Providers**: STT, translation, TTS and summarization sit behind interfaces in
  `packages/ai-providers`; the API picks implementations from env, see
  [AI Provider Abstraction](./architecture/ai-providers.md).
- **Files**: kebab-case, long and descriptive (`password-change-revocation.ts`), so a
  file name says what it holds. A file past ~200 lines is a prompt to look for a real
  seam, not a hard limit (`CLAUDE.md`).
- **Comments** explain the invariant or the reason, not the change. Plan IDs, phase
  numbers and audit labels do not go in comments, test names or commit messages.

## UI

- Components come from shadcn, generated by the CLI into `packages/ui`
  (`packages/ui/components.json`) and re-skinned to the tokens in
  `packages/ui/src/tokens.ts`. Web and the extension popup import them from
  `@chatofy/ui/react`; don't hand-write a component shadcn has.
- The meeting overlay and mobile do not use them, for reasons in
  [design-guidelines.md](./design-guidelines.md).
- Design rules are specs, not review comments: `apps/web/src/design/*.spec.ts(x)` gates
  token parity, contrast floors, the type scale, the app skin and the accent budget;
  `apps/web/src/components/marketing/accent-budget.spec.tsx` gates the marketing page.

## Tests

- Vitest everywhere a workspace has a `test` script; specs sit beside the code as
  `*.spec.ts(x)`.
- API: `test` (unit), `test:e2e` (in-memory substrate), `test:e2e:db` (real Postgres).
- Extension: `test` (unit) and `test:e2e` (`node e2e/run.mjs`, loads the built
  extension into Chromium).
- Build-output checks: `verify:build` in `packages/ui` and `apps/extension` (content
  script CSS, MV3 CSP).

## CI gate

`.github/workflows/ci.yml` runs on every PR and on `main`: Lint, Type check, Test, API
e2e, API e2e (Postgres), Build (+ `verify:build`), Extension e2e, Display ITN gates, TTS
sidecar unit tests, Realtime replay, Supply chain. `main-failure-alert.yml` raises an
alert when `main` goes red; deploy is in [deployment-guide.md](./deployment-guide.md).

## Commits

Conventional Commits, checked by commitlint (`.commitlintrc.cjs`,
`@commitlint/config-conventional`) from the husky `commit-msg` hook. No AI attribution
trailers (`CLAUDE.md`). Never commit `.env` files, keys or credentials.
