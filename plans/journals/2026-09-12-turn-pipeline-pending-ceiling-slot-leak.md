# Turn-pipeline pending-ceiling slot leak

Production logs showed 'A connection may hold 3 turns at once' followed by 'The turn was closed after too long without audio' while the user pressed Pause. Diagnosis (proven by the [chatofy] console log the user supplied): TurnPipeline.enforcePendingCeiling evicted ANY turn holding pending audio, including one whose client.session.start had already been sent. The client forgot the turn but the server still held its slot, so the client under-counted, the next start earned too_many_turns, and the orphaned server-side turn was reclaimed 30s later by the idle sweep. Pause itself was proven innocent: capture is gated at node.port.onmessage via captureStopped, and the in-flight drain (transcript, playback, mic badge) is deliberate design. Fix (packages/realtime-client/src/conversation/turn-pipeline.ts): a 'waiting' turn (start never sent, server never saw it) is still forgotten whole with reason dropped_pending; a turn whose start went out (handshaking/ending) keeps its lifecycle but has its pending audio discarded, so onReady flushes nothing and, with capture already finished, sends client.session.end immediately - releasing the server slot by the client's own hand. The discarded milliseconds are accumulated into a discardedMs counter and folded into heldMs in the metrics row so a shed turn does not read as one nobody spoke into (reviewer finding; the old code filed no row at all for these turns, so not a regression). Tests: rewrote the pending-ceiling describe block with three specs - handshaking turns shed audio but are never forgotten (asserts heldMs visibility), waiting turns are still forgotten whole, and the exact production race (slot frees, start goes out, ceiling fires before ready, turn survives, late ready sends end). Both key specs fail on the pre-fix code (verified via git stash). Full package: 331 passed / 1 skipped, tsc clean. Scope deliberately excluded: pausing does not stop the MediaStream track (mic badge stays on) - user confirmed keep current design; MAX_IN_FLIGHT stays 3.
