## Open questions

1. SFU choice (LiveKit / mediasoup / Pion) — user decision; table in VCA Open decisions §1. Footprints there are unmeasured; LiveKit/mediasoup/Pion capability rows are general knowledge, not verified against current upstream docs in this pass.
2. Media path through production: prod is published via Cloudflare Tunnel; whether to open a host UDP port or rely on TURN is unresolved for every option.
3. Billing tables: keep as optional design, or drop? Default vi STT (Zipformer-30M) is CC-BY-NC-ND academic-only, so any commercial billing would also force an STT model swap.
4. Persisting CAM++ vectors contradicts the current "no stored voice" rule; with per-participant tracks, is acoustic attribution needed at all?
5. Recording storage: current R2 bucket is public-read; private bucket or other store needed before recordings.
6. Schema conventions (UUID vs cuid, User FKs vs plain ownerId, enums vs text) left unreconciled in the SQL — the implementer should align with schema.prisma.
7. CAM++ vector dimension (doc said 512D) not verifiable from source; read from the model at runtime.
8. VCA §9 condensed (duplicate of §3) to meet the 800-line cap — confirm acceptable to the author.
